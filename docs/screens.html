Dashboard GET /

The home screen. Shows a grid of action cards — one per major module. Acts as the main navigation hub since there is no persistent sidebar. Compact one-pager version: docs/dashboard_cards.html (one mini-card per dashboard card — keep in sync when cards change).

Cards Deadlines & Burning (2026-08-11, red card, FIRST — open count badge, plus "N overdue"/"N due today"). Then the order fixed by Marina (2026-07-16), daily work first: Inbox (pending count badge) · Import · Core South Spillover · Retail · ECOM Gatekeeper · ECOM · Defects · Known Production Issues (renamed 2026-08-06 from "Known Prod Defects"; count badge — the register outlives the spillover work; the Spillover-page link stays too) · Export & Backup (teal accent — report exports, Email Reports link, and the DB-backup section folded in 2026-07-18) · Meeting Prep · Retail Requirements Tracker (unresolved count badge, amber accent) · Topics (active count badge, green accent) · Follow-ups · Links · Contacts · Shelf (item count badge, purple accent) · Encouragements (undelivered count badge) · CS Follow-Up Tracker · To-Do · Teams Chats (2026-07-16, manage registry + pin for the 💬 widget) · Message Types (2026-07-16, ✉️ builder reference) · Enhancements (open count badge) Deadlines & Burning popup (2026-08-11) A modal (_urgent_popup.html) opens on the dashboard whenever something in Deadlines & Burning is open — "really push my nose into those topics" [USER]. Lists the open entries most-urgent first with their category chip and overdue/today marker, and each can be ticked off right in the popup (AJAX), so it is useful rather than just noise. Dismissed with "Got it", Esc, or a backdrop click; the dismissal is remembered per day in localStorage (urgent-popup-seen), so it is back tomorrow but does not nag on every dashboard visit. Ticking the last open entry closes it automatically. No open entries → no popup at all. Primary action Run Import — triggers a POST to /import and redirects to the Import Result screen Export Reports AJAX button (teal card) — POST /export-reports — saves dated snapshots to report_export/ (gitignored): HTML + PowerPoint for the Retail and Spillover reports, and (2026-08-26) HTML-only for the Delegated status report + numbers (same clean download-mode renders as their ⬇ Download HTML buttons). Spillover uses the current row selection. Folder path configurable via report_export_folder in config/settings.yaml. DB backup (2026-07-18, in the Export & Backup card) Section under the export buttons (folded in per Marina — no own card). Copies the SQLite DB to the configured backup_folder (machine-specific — settings.local.yaml, e.g. the external drive) AND mirrors data/uploads (screenshots/PDFs — the DB only stores filenames!) incrementally to <backup_folder>/uploads: missing files copied, existing skipped, deleted-in-app files linger (backup, not sync). Buttons: Overwrite copy (replaces chaosco_backup.db) / New dated copy (chaosco_backup_<timestamp>.db). A "Last backup: … (N days ago)" reminder line sits under the buttons (amber when older than 7 days). Uses sqlite3's backup API — consistent snapshot even mid-write. POST /backup, logic app/backup.py. A browser page cannot open a native pick-any-folder dialog — the configured folder is the deliberate design. Navigation Each card contains a link button to the corresponding list screen. The site title in the header also links back here from every page.
Inbox GET /inbox

Daily capture pad. Paste notes and screenshots during the day, then file each item to its destination (Defect, Retail test case, Spillover, ECOM, Gatekeeper ticket, Test Learning, Follow-up, Shelf, Topic, Contact, Link, or Known Prod Issue [added 2026-08-06]) when ready. Unfiled items stay here until moved or deleted. Dashboard card shows pending count badge.

Add item Heading (optional) + large textarea + 📷 Add screenshot or 📎 Attach file or Ctrl+V paste. Items appear in reverse-chronological order. Reference fields (2026-07-16) Optional per item: Order number · SolMan ID · Jira ID (columns on notes, shown as coloured chips, searchable) + a route-to dropdown (Contact / Link / Follow-up → that module's Incoming bucket). Editable in the inline edit form. Designed as the landing zone for a future Power Automate Teams import. ⚡ Auto-file (2026-07-16) Header button → preview dialog: "Will move" list (checkboxes, all pre-ticked) + "Stays in the inbox" with reasons — nothing moves without confirm. Targets: Jira tickets (notes land at ('jira', key) — visible on the Gatekeeper ticket + ECOM expander) and Defects; routed items go to the module's Incoming section. Matches are recomputed server-side on apply. APIs: GET /inbox/autofile/preview · POST /inbox/autofile/apply (ids CSV). Text search (2026-07-16) Search box in the Pending card header — live client-side filter (no reload) matching heading, note text, and attachment names, case-insensitive. Button labels are deliberately excluded so e.g. "edit" doesn't match every item. While filtering, the count badge shows shown / total; ✕ or Escape clears. Only rendered when items exist. Widened 2026-07-18 (grows with the card header, larger font). Per-item actions Edit — inline toggle; updates heading and note text

Catch-all store for notes and observations that don't belong to a specific defect, test case, or spillover item yet. Items have a heading, optional area, and optional category. Dashboard card shows total item count with a purple accent. Reachable from the Inbox filing picker (Shelf option) or directly from the dashboard.

When 2+ rows are checked a "Combine N selected ›" button appears above the table. Clicking it opens a modal listing the selected items as radio buttons — pick the primary item to keep; all notes from the others are moved into it and the secondary rows are deleted. Route: POST /shelf/combine (fields: primary_id + item_ids[]). Redirects to the primary item's detail page. A "Select all" checkbox in the header selects every visible row. From Inbox Selecting Shelf in the Inbox filing picker shows area + category text inputs (no search — a new shelf item is always created). Route: POST /inbox/<note_id>/file-to-shelf. The inbox item's heading becomes the shelf item's heading; the note is re-parented.
