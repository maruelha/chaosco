Documentation Map

Every doc, its job, its update trigger, its enforcement. Generated 2026-09-01 by tools/gen_docs_map.py — the job lines are hand-written in that script's registry, the file list and dates come from the filesystem and git. Regenerate after adding or removing a doc (the suite fails until you do).

The concept [agreed 2026-09-01]:

1. Every doc has ONE job. A fact is described at exactly one altitude; other docs may name it, never re-describe it. When you cannot tell two docs apart, one of them has stopped doing its job.

2. Facts are generated or tested, meaning is hand-written. Anything a script can derive from the code (routes, tables, columns, dates) must not depend on someone remembering to type it. Only the WHY is written by hand — a script can never know why.

3. story → rule → test. A lesson (lessons_learned.md / ways_of_working.md) that keeps mattering becomes a guideline (coding_guidelines.md); a guideline a machine can check becomes a test. Every promotion makes the next review shorter.
